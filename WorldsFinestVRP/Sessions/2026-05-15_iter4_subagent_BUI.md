# Iter4 sub-agent BUI -- B0pp control surface + snapshot viewer

Implemented the WorldsFinestVRP web UI Phase B0pp control surface and side-by-side snapshot viewer. New `webui/processes.py` introduces a `ProcessRegistry` singleton owning `subprocess.Popen` lifecycle for two whitelisted bench scripts (`cb_scaled_rebench`, `v1_leaderboard_solve_auto`); on Windows it spawns with `CREATE_NEW_PROCESS_GROUP | DETACHED_PROCESS` and `os.kill(pid, CTRL_BREAK_EVENT)` for a graceful stop that propagates to `ProcessPoolExecutor` workers, then escalates through `terminate()` and `kill()`. `validate_args` enforces a per-script flag whitelist, restricts `--include` choices, rejects shell metacharacters (`;|&<>$\``\\n\\r`), and forbids `--out` paths outside `bench/runs/` (no `..`, no absolute paths). A background reader thread per process pumps stdout into `bus().add_log()` and posts `running` -> `completed`/`failed`/`stopped` agent lifecycle events. `webui/app.py` gained five new routes -- `POST /control/run`, `POST /control/stop`, `GET /control/list`, `POST /control/clear-snapshots` (hard-isolated to `webui/static/snapshots/*.png`, no recursion), `POST /control/build-report` (touches `WorldsFinestVRP/Progress_Report.html` mtime; TODO note left for the future build script), plus `GET /viewer` and an `OPTIONS` CORS preflight. `serve()` now also calls `set_server_url(...)` so spawned bench subprocesses inherit `SVRPTW_WEBUI_URL` and POST events back to `/event`. The existing `/event` POST contract is preserved. `webui/templates/index.html` got a sticky top action bar (Reset bus, Clear snapshots, Run bench dialog, Stop, Viewer, Publish report) using the existing dark theme and CSS variables, with a modal run dialog (script select, workers `1..8`, extra-args text) and a 3-second toast slot. `webui/templates/viewer.html` is a new full-page side-by-side viewer with two `<select>` stream pickers (defaults: most-recent and second-most-recent stream), prev/next/play (200 ms), `i / N` frame counter, follow-latest toggle, and `Left`/`Right`/`Space` keyboard handlers. Tests: created `tests/integration/__init__.py` and `tests/integration/test_webui_control.py` covering the run/list/stop/clear-snapshots happy path (skips when `instances/v1/OSM-*-N100-I003.json` is missing), three validation-error cases (`unknown script`, `unknown flag`, `unknown --include` -> all 400), the `/viewer` route, and `/control/build-report` -> `/reports/progress`. All four integration tests pass; `pytest tests/unit -q` is green (the only intermittent failure on a combined run is the pre-existing wall-clock-budget flake `test_basin_jump_default_off_unchanged_behaviour`, unrelated to this change). Smoke verification against a live server on port 8769 confirmed `/viewer` 200, `/control/list` 200 with `{"procs": []}`, `/control/clear-snapshots` 200, `/control/build-report` 200, and 400s on bad script / bad flag inputs. Stdlib only -- no new pip deps; bind stayed `127.0.0.1` only; all writes done via `mcp__Desktop_Commander__write_file` in `<=30`-line chunks.
