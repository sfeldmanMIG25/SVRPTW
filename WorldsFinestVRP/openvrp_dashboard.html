openvrp_native wins wall + memory at every N — sub-second across the board, lowest RSS at small N (48 MB at N=50 vs 165-185 MB for others). It trades ~15 % objective quality vs the 30 s PyVRP/OR-Tools result for a 375× speedup at N=250 and a 5–10 % memory edge at N=100/250. Bug found by this bench and fixed: the openvrp adapter was assigning every instance the same string id ("openvrp-0"), which collided with svrptw's _CUST_DICT_CACHE and raised KeyError on the second-run customer ids. Fixed by hashing (N, OD shape, t0) into a unique id.
